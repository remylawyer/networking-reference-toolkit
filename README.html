README and publication notes

Three practical editions for reference and troubleshooting:

  • Basic Networking — foundational terms, first-response checks and guided fault isolation.
  • Intermediate Networking — subnetting, VLAN/trunk/SVI, routing, DHCP/DNS and packet-level diagnosis.
  • Advanced Networking & CCNA Preparation — verification patterns, routing/policy scenarios, IPv6, operations, automation safety and exam-version notes.

Each edition is provided as online HTML, printable PDF and editable DOCX. The HTML versions include a visual troubleshooting decision flow and accessible text description.

Publication and verification disclosure

This toolkit was developed with assistance from AI tools for drafting, organisation and refinement. The content was reviewed by the author against their own networking knowledge and learning, with the aim of improving accuracy, clarity and practical usefulness. The resource is subject to ongoing technical review, fact-checking against authoritative documentation, and refinement based on external feedback. Readers should verify critical procedures against current vendor documentation and test configurations in an appropriate lab or authorised environment.

A note on scope

The three editions share a substantial common core. The cheat sheets, troubleshooting playbooks, command references and resource directory appear in all three; what changes with depth is the guidance, the worked scenarios and the edition-specific field guide at the end of each book. Read this as one reference presented at three depths, not three unrelated documents.

CCNA exam-version note

Cisco states that the 200-301 CCNA v1.1 exam remains available through 2 February 2027 and v2.0 testing begins 3 February 2027. The advanced edition includes a forward-looking v2.0 coverage map. Candidates should verify the blueprint that matches their exam date on Cisco's official site: https://www.cisco.com/web/go/ccna/

Use safely

  • Start with read-only checks and capture a baseline.
  • Use commands only on systems you are authorised to inspect or administer.
  • Do not store passwords, private keys, tokens or sensitive configuration data in public repositories.
  • Treat results as evidence, not proof beyond what a test actually measures.
  • Confirm platform/version-specific syntax and approved change/rollback procedures before making changes.
